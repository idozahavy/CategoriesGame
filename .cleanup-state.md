## Flagged for review

- Import auto-sorting is not configured. The code scheme (CODESTYLE.md v1.2.0) is locked and user-approved; adding an eslint import-sort plugin would amend it, so this is left for the user to decide.
- GameState booleans (`endless`, `funFacts`, `speedScoring`, `wikidataCheck`, `remote`, `statsRecorded` in types.ts) don't follow the is/has predicate convention, but they are persisted in IndexedDB saves and cross P2P — renaming would orphan existing saves unless a migration is added. Left as-is.
- `buildHostRoom` in p2p.ts is a ~189-line closure over live connection state. A split is possible but risky for a behavior-preserving pass; recommend doing it alongside the planned TV-scale work.
- NewGame.svelte (933 lines), Round.svelte (734), Join.svelte (553) exceed comfortable size; CODESTYLE mandates one route-level component per screen, so a split means extracting child components into src/lib/ui or a screen-parts folder — a design decision, not applied.
- `dictCache` (validation.ts): two concurrent checks of the same word can fire duplicate Wiktionary fetches (no in-flight dedupe). Rare and harmless; fixing it needs care because 'error' results are deliberately not cached. Optional.
- All lookup caches are session-lifetime and unbounded (factCache, wikidataCache, dictCache, learnedCache, word-list cache). Bounded in practice by words played in one session; a `wikidataCache` 'nofit' is never rechecked within a session. Acceptable, noted.
- No test suite exists. Untested critical paths (report only): game.ts scoring/speedRanks, p2p.ts message type guards + host seat reclaim, validation.ts checkWord mode matrix. These are pure or guard-based and would unit-test well if tests are ever added.
